## Workflow separation

- `workflows/workflow_simu` 与 `workflows/workflow_batchsimu` 是两套完全独立的 workflow，不共享节点、A-F 产物、run 目录、SQLite 数据库或控制流 handoff。
- `workflow_simu` 自包含 A-M：少量候选、agent 在环、同步 `wqb sim create`、个体 K/L 诊断，M 才允许记录或执行提交。
- `workflow_batchsimu` 自包含 A-M：模板族密度研究、固定 settings、分族无放回抽样；J 只负责 `wqb sqlitesimu` 入库、启动 worker 和交接，K 分析并选择，L 慢速终检，M 才允许 Alpha submit。
- batch worker 运行期间 agent 不参与逐条回测；K 只能在权威 run 终态后分析 execution、错误、质量分布和 `simued_alpha_is_pnl` correlation clusters；L/M 只能处理当前 batch 自己的真实 Alpha。
- batch 不得向另一套 workflow 移交或接收 candidate、alpha、结果或控制流；累计目标未完成时必须从本流程 A 创建新的独立 batch。
- 新 run 分别放在 `research_runs/workflow_simu/` 与 `research_runs/workflow_batchsimu/`；2026-08-18 的历史 batch 保持原路径和数据库，不迁移，但已按用户要求停止并持久化取消状态。
- batch template 必须遵循 `workflows/workflow_batchsimu/template_contract.md`：H 使用中英文名、逻辑、placeholder 和 `template_LLM` 源码格式，I 生成完整 version/epoch/hash lineage，K 固定输出三段机器统计和逐模板评估。
- `expression_hash` 标识含 header 的完整源码，`calculation_hash` 标识可执行正文；跨 epoch/run 必须用 `calculation_hash + settings_hash` 排除已经测试过的等价计算。
- 固定模板报告只做格式化和基础完整性筛查，不能替代 F 的 denominator/Wilson contract 或 K 的 IS-PnL clustering，也不能单独授权候选进入 L。
- `SIMULATE_UNKNOWN` 逐 experiment 隔离且永远不自动重跑、不选择、不提交；仅由 unknown 导致的 `BLOCKED` run 在 READY coverage 达到 F 预注册门槛时，可以分析 READY 子集。
- `SELF_CORRELATION`、`DATA_DIVERSITY`、`PROD_CORRELATION`、`REGULAR_SUBMISSION` 的 `PENDING` 是 submission-only 状态，K deferred 到 L；simulation-resolved check 的 `PENDING/FAIL/ERROR` 仍阻止候选进入 L。
- live data-fields endpoint 不暴露 scalar unit、update cadence 和 missing sentinel 时不得伪造字段契约；batch 只允许 unary 或同 dataset、同量纲描述、显式定向的 pair 例外进入，并强制 `unitHandling=VERIFY`、`nanHandling=ON`，契约状态记录为 `TYPE_CONFIRMED_SERVER_UNIT_VERIFY_REQUIRED`。服务器确定性 unit 错误在 K 归入 family error，不能归为平台故障。

## Authentication recovery

- 自动续期必须覆盖 `204 / 401 / 429`，不能只覆盖 `401`；依据是 WQBRAIN 环境中 `wqb.WQBSession` 的 `expected` 判定。
- 所有 `WqbClient` 默认启用全局自动续期：每轮认证最多 3 次，业务请求最多额外重放 3 次，成功后更新 cookie。
- `sqlitesimu` 在 CoreClient 耗尽后独立补 5 次显式重登；额外层不递归进入 CoreClient 的重试循环。
- 两层均耗尽时，`204 / 401 / 429` 不得消耗 runtime 失败预算或写成 `PERMANENT_FAILURE`，任务保持 RUNNING 并延期恢复。
- 为保持与 `WQBSession` 一致，`POST /simulations` 返回 `204` 时也会重登并重放；认证接口自身禁止递归续期，登录仅接受 `201`。
- 旧 cookie loader 曾把同一个值同时挂到父域和 API host，导致续期后同一进程混发新旧 cookie；登录前必须清除旧 BRAIN cookie，旧扁平格式只加载一个 host cookie。
- alpha 等待和 simulation 轮询不得直接绕过 `WqbClient`，也不再保留局部 Basic Auth 重试。
