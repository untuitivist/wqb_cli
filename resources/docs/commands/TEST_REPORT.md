## Polling Policy Verified

The CLI records `response.wait_events` when it polls through `Retry-After`.
When progress is near sticky values `0.15` or `0.35`, the CLI multiplies the platform wait time by `10`.
This avoids noisy frequent polling during known platform stalls.
The default total wait cap for `sim get` is `900` seconds, i.e. 15 minutes.
If the next sleep would exceed this cap, the CLI returns the latest response with `response.wait_timed_out = true`.

## Concurrency Rules

These are operating constraints for external schedulers that call the CLI:

- `REGULAR_FASTEXPR_MULTI` supports up to 10 expressions per POST body.
- Recommended `REGULAR_FASTEXPR_MULTI` batch size: 10 when `region != "GLB"`, 5 when `region == "GLB"`.
- `REGULAR_FASTEXPR_MULTI` may fail when a batch has too many or too complex expressions; reduce batch size before changing the API flow.
- `REGULAR_PYTHON` cannot use multi-simulation; use one POST body per expression.
- `SUPER` uses one SUPER POST body per simulation.
- Concurrent `SUPER` simulation requests: at most 3.
- Concurrent `REGULAR` simulation requests: at most 8 when `region != "GLB"`, at most 4 when `region == "GLB"`.
