# D 选主塔

这是一个 skill-only 决策节点，不是执行节点。

## 输入来源

- `B_主题_平台机会`
- `C_金字塔现状`

## 优先级顺序

1. 点塔第一优先级：优先选择最有机会尽快点亮的塔 (本季度提交满3个即为点亮)
2. `fundamental < 15%` 是硬约束，不得违反
3. 在满足前两条的前提下，优先成熟竖向塔
4. 再考虑主题/平台机会是否加分
5. 仍然尽可能远离 `D0`

## 必须回答的问题

- 当前最值得研究的主塔是什么
- 为什么选它，而不是第二候选
- 这个主塔当前距离点亮还有几条
- 这个主塔是否违反 category 集中度约束
- 这个主塔是否位于成熟竖向塔中
- 这个主塔是否不必要地靠近 D0

## 硬约束规则

- `fundamental` 在同一竖向塔中的占比不得超过 `15%`
- 其他 category 在同一竖向塔中也尽量不要过度集中
- 点塔是第一优先级
- 在点塔目标相近时，优先成熟竖向塔
- 如果要新开地区，必须尽量多交这个竖向塔，避免孤立单塔
- 尽可能远离 `D0`

## 输出要求

必须形成一个结构化主塔结论，至少包括：

- `target_tower`
  - `region`
  - `delay`
  - `category`
- `lighting_priority_judgment`
- `why_this_tower`
- `why_not_second_choice`
- `category_concentration_judgment`
- `vertical_maturity_judgment`
- `d0_avoidance_judgment`

## 禁止事项

- 不要在这个节点开始看 dataset / datafield
- 不要在这个节点生成表达式
- 不要把“主题加分”误当成比“点塔优先”更高的规则
